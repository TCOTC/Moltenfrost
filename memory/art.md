# 美术与第一人称

科幻设施风格、PBR 贴图、环境反射、第一人称表现，以及用来核对画面的工具。全部为实测结论。
玩法与关卡几何在 `gameplay.md`；元素的颜色定义在 `scripts/element.gd`。

## 美术方向

- 低饱和冷灰蓝金属为底、大面积暗部；亮部几乎全部来自自发光（灯带、能量场、能量件）。
- 元素色是画面里唯一的饱和色，用来区分归属。
- 集中定义在 `scripts/art/palette.gd`：颜色、贴图与材质都只在那里写一次。
- 几何全部程序化生成（`CharacterRig` 出角色与武器，`Facility` 出设施构件，`level_01.gd` 摆关卡）。

## 去塑料感的两条前提（2026-09-24，这是本轮改动的主因）

之前所有表面都是纯色材质，看起来像塑料。根因不是「没贴图」，而是两条：

1. **金属没有东西可反射。** `metallic` 高的材质几乎不漫反射，显示的全部是环境反射。
   当时场景的反射来源只有一个纯色环境色，于是所有金属面反射到同一颜色——
   这在物理上与「上了漆的塑料」完全一致。
   修法：HDRI 天空只用于反射与间接光（`Environment.sky` + `ambient_light_source = SKY` +
   `reflected_light_source = SKY`），而 `background_mode` 仍是纯色，**不显示天空**——
   封闭设施里看到室外天空很突兀。
2. **表面没有微观起伏。** 真实金属有划痕、拉丝、磨损，这些都在法线与粗糙度贴图里。
   修法：ambientCG 的 PBR 贴图（反照率/法线/粗糙度/金属度/环境光遮蔽）。

配套的两项：**屏幕空间间接光（SSIL）** 让灯带与亮面把光反弹到附近表面（纯直接光下金属很平），
以及 SSAO。tonemap 从 ACES 改为 **AgX**：本场景小面积高亮的灯带多，AgX 更能保住亮部色相。

贴图与颜色三条约定：

- **`TINT_*` 是乘数，不是颜色。** 最终反照率 = 贴图色 × tint，因此选值时按
  「目标明度 ÷ 贴图明度」反推，而不是直接写想要的颜色。
- **`METAL_*` 是直接反照率**，用于不带贴图的小构件（`Palette.metal`）。它的值就是最终线性明度，
  因此比 `TINT_*` 小得多。拿 `TINT_*` 去传给 `metal()` 会让小构件亮得像灯泡。
- **三平面投影**（`uv1_triplanar`）是必需的：程序化长方体每面 UV 都是 0～1，
  一张贴图会被拉伸到整块板上（几米宽的地板会把 1K 贴图铺成一层糊）。
  静止设施用世界坐标（相邻板材之间连续），角色与武器用局部坐标（贴图跟着物体走）。

素材来源、许可与已排除的条目见 `THIRD_PARTY.md` 第五节；下载与重建用 `tools/fetch-assets.mjs`。

## 数值（都是实测算出来的，不要凭感觉改）

- 相机竖直 FOV **62°**（`player.tscn`）。曾用 82°，走廊被拉成鱼眼。
  推导：Godot 的 `Camera3D.fov` 在默认 `keep_aspect` 下指**竖直**视角，
  16:9 屏幕上半宽/半高比 = tan(hfov/2)/tan(vfov/2) ≈ 1.78。
  距相机 d 处的可见半高 = 0.60d，半宽 = 1.07d。摆第一人称物体先算这两个数。
- **第一人称武器的尺寸关键是它的近端而不是中心。** 枪托在基准点之后 0.16 米，
  所以近端距相机只有 0.55 米；把基准点放在 0.55 处时近端只剩 0.39 米，
  那里的可见半高只有 0.23 米，0.11 米高的机匣就占掉画面半高的一半（实测变成一大块）。
  现取值 `BASE_POSITION = (0.185, -0.185, -0.84)`。手的位置必须由枪的握把反推
  （见 `CharacterRig.build_hands`）；改枪的位置时两只手要一起改。
- 武器的三个轴都故意偏了一点（`BASE_ROTATION = (2.5, 7.0, -2.0)`）：
  正对镜头的长方体在画面上就是一个矩形，看不出厚度，这就是「像个盒子」的直接来源。
- 金属度：设施 1.0；**角色 0.55、武器 0.70**。全金属时角色站在没被灯照到的位置就是一因黑。
- 角色装甲明度约 **0.31**（贴图 0.328 × 染色 0.95）。实测 0.13 时角色在设施里仍是一团暗影，
  而**角色任何时候都必须能被对方看见**，这是双人协作的前提。
- 装甲贴图铺贴 **0.13 米**。取 0.30 米时一块 0.4 米的装甲正好只铺到一片贴图，
  整块面上是同一个斑块，看起来像石头而不是金属（贴图的斑块尺度变成了物体的尺度）。
- **rim（边缘光）**：角色 0.35、武器 0.30、装甲暗件 0.25。它不是自发光，
  而是在掠射角叠一层高光，给物体描一条紧贴轮廓的亮边——让角色在暗处可辨的标准做法，
  比加自发光干净得多。`rim_tint = 0.4`（既保住物体色相又比全取反照率更亮）。
- 环境：背景近黑、`fog_density 0.018`、`glow_hdr_threshold 1.10`、`glow_intensity 0.50`、
  AgX + `tonemap_agx_white 6.0`、HDRI 能量 **0.30**（取 1.0 会把设施照成白天；取 0.1 以下金属又变回纯色）。
- 池面发光强度 1.0、槽壁灯 1.1、门头灯 2.0～2.8。实测 1.8 时池面在 glow 后饱和成白色。
- 性能：带显示运行实测 120 fps、帧时 8.3 ms（RTX 4050 Laptop）。贴图与后处理的开销可接受。

## 四个踩过的坑

- **两个面共面会互相遮挡**。槽体顶面与液面同在 y=0.10 时深度冲突，
  半透明的液面被深色槽面遮住 → 池子看起来是黑的。任何叠放的两个盒子都要错开几厘米。
- **深色底上的单通道自发光会让物体变成该颜色**。武器与装甲原本带元素色的自发光
  （0.10～0.25），在没有其他光照的暗处，红色通道因此远超其他两通道，枪身变成发红的塑料。
  结论：**自发光只给能量件**（喷嘴、能量瓶、瞄具、面缝、核心），枪体与装甲一律不发光。
- **`add_child` 会立刻执行该节点的 `_ready`**。带脚本的节点（池、按钮、门、出口）
  必须先建好全部子节点、设好脚本与导出属性，最后才 `add_child`；
  否则脚本的 `_ready` 里访问 `$Mesh` / `$Collision` 会以 `Node not found` 失败。
  同类坑：这类脚本不能用 `Net.is_server()` 决定「要不要处理」，因为节点先于 `main.gd` 就绪，
  那时还没有会话，而离线状态同样被判为服务端；改在 `_physics_process` 里每帧判断。
- **`Sky.radiance_size` 收的是枚举序号，不是像素数**。直接传 512 会被拒绝：
  `Index p_size = 512 is out of bounds (RADIANCE_SIZE_MAX = 7)`。
  实测 4.7.2 的对应关系是 32/64/128/256/512/1024/2048 → 0/1/2/3/4/5/6。

## 截图核对

无头自检查不出美术问题，这类问题只有看到画面才能判断。两个入口：

| 命令 | 用途 | 输出 |
| --- | --- | --- |
| `& <godot> --path <项目> -- --port 0 --capture` | 世界观 8 张预设机位 | `build/shots/01_spawn.png` 等 |
| `node tools/capture-remote.mjs` | **对端角色**造型 4 张（第一人称看不到自己的身体） | `build/shots/r1_front.png` 等 |

- 取景用**独立自由相机**，不用角色自带的相机：角色是 CharacterBody3D，
  相机挂在它身上，机位会被重力与碰撞带动，截出来的图与预设对不上（实测拍成一整面墙）。
- 取景对端角色时要对 **`Visual` 子节点**：远端角色的根节点位置是收到的原始位置，
  实际渲染的身体在 `Visual` 上，两者相差一个插值偏移（长帧时实测差到 3 米以上）。
- 每个机位等 24 帧（SSAO 与 TAA 要累积），随后 `await RenderingServer.frame_post_draw` 再取纹理；
  不等待会截到上一帧的机位。
- 带超时保护：任何一步失败都会退出并报错，否则游戏窗口会一直开着、终端被占住。
- **`build/` 下必须有 `.gdignore`**：否则引擎会导入截图 PNG，在 `build/shots/` 里生成一堆 `.import`。

### 已知限制：帧率低于 10 fps 时远端显示会持续落后

`RemoteInterpolator` 每帧最多推进 `MAX_FRAME = 0.1` 秒，而 `_render_time` 的追赶上限是 1.1 倍。
因此当实际帧长超过 100 ms 时，显示时钟前进得比真实时间慢，且**永远追不回来**，
表现为远端角色越来越滞后（实测在截图工具造成长帧时，几秒内拉到 3～4 米）。
正常帧率下不会触发；要修得让追赶速率随帧长放大，或去掉 `MAX_FRAME` 的上限。

## 截图核对（`--capture`）

- 无头自检查不出美术问题，这类问题只有看到画面才能判断。工具在 `scripts/dev/capture_rig.gd`，
  用法：`& <godot> --path <项目> -- --port 0 --capture`，
  输出到 `build/shots/`（8 张预设机位，含低头看武器与高处俯视）。
- 实现要点：每个机位等 24 帧（SSAO 与 TAA 要累积），随后 `await RenderingServer.frame_post_draw`
  再取 `get_viewport().get_texture().get_image()`；不等待会截到上一帧的机位。
- 带 60 秒超时保护：任何一步失败都会退出并报错，否则游戏窗口会一直开着。
- 机位必须避开隔墙（x∈[-0.35,0.35] 的主厅区域），否则截到的是墙面。
